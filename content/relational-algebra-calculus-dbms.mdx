# Relational Algebra, Tuple & Domain Relational Calculus (TRC/DRC)

## 1. Formal Query Language Paradigms

In relational database theory, query languages are formal mathematical notations for retrieving and manipulating stored relations. They fall into two broad computational paradigms:

```text
                           Relational Query Languages
                                       |
                   +-------------------+-------------------+
                   |                                       |
                   v                                       v
        Procedural (Prescriptive)              Declarative (Non-Procedural)
     - Specifies WHAT data to retrieve       - Specifies WHAT data to retrieve
       and HOW (step-by-step) to get it        WITHOUT specifying how to compute it
     - Example: Relational Algebra           - Example: Tuple & Domain Calculus (TRC/DRC)
```

- **Relational Algebra**: An algebraic system consisting of relations and a set of operators that take one or more relations as input and produce a new relation as output (**closed algebra**).
- **Relational Calculus**: A mathematical system based on first-order predicate calculus.

---

## 2. Fundamental Relational Algebra Operators

There are **five independent fundamental operators** in Relational Algebra. No single operator from this set can be expressed in terms of the other four:

$$\mathcal{B} = \{ \sigma \text{ (Select)}, \pi \text{ (Project)}, \times \text{ (Cartesian Product)}, \cup \text{ (Union)}, - \text{ (Set Difference)} \}$$

*(Plus the auxiliary Rename operator $\rho$).*

### 2.1 Selection Operator ($\sigma$)

- **Purpose**: Horizontal filtering. Selects tuples that satisfy a given boolean predicate $p$.
- **Notation**: $\sigma_p(R)$
- **Formal Definition**:
$$\sigma_p(R) = \{ t \in R \mid p(t) = \text{True} \}$$
- **Properties**:
  - **Degree (Arity)**: Unchanged: $\text{deg}(\sigma_p(R)) = \text{deg}(R)$.
  - **Cardinality**: $0 \le |\sigma_p(R)| \le |R|$.
  - **Commutativity**: $\sigma_{p_1}(\sigma_{p_2}(R)) \equiv \sigma_{p_2}(\sigma_{p_1}(R)) \equiv \sigma_{p_1 \land p_2}(R)$.

### 2.2 Projection Operator ($\pi$)

- **Purpose**: Vertical filtering. Selects specified attribute columns and **eliminates duplicates** (since mathematical relations are sets, not multisets).
- **Notation**: $\pi_{A_1, A_2, \dots, A_k}(R)$
- **Properties**:
  - **Degree**: $\text{deg}(\pi_{A_1, \dots, A_k}(R)) = k$.
  - **Cardinality**: $1 \le |\pi_{A_1, \dots, A_k}(R)| \le |R|$ (if $R \neq \emptyset$).
  - **Idempotence**: $\pi_{L_1}(\pi_{L_2}(R)) \equiv \pi_{L_1}(R)$ provided $L_1 \subseteq L_2$.

### 2.3 Cartesian Product (Cross Product, $\times$)

- **Purpose**: Combines every tuple of relation $R$ with every tuple of relation $S$.
- **Notation**: $R \times S$
- **Formal Definition**:
$$R \times S = \{ t \cdot s \mid t \in R \text{ and } s \in S \}$$
- **Properties**:
  - **Degree**: $\text{deg}(R \times S) = \text{deg}(R) + \text{deg}(S)$.
  - **Cardinality**: $|R \times S| = |R| \times |S|$.

---

### 2.4 Union ($\cup$) & Set Difference ($-$)

For Set Union and Set Difference, relations $R$ and $S$ must be **Union-Compatible (Type-Compatible)**:
1. $R$ and $S$ must have the **exact same degree** ($\text{deg}(R) = \text{deg}(S) = n$).
2. The domain of the $i$-th attribute of $R$ must be identical to the domain of the $i$-th attribute of $S$ ($\text{dom}(A_i) = \text{dom}(B_i)$ for all $1 \le i \le n$).

#### Definitions & Bounds:
- **Union**: $R \cup S = \{ t \mid t \in R \lor t \in S \}$.
$$\max(|R|, |S|) \le |R \cup S| \le |R| + |S|$$
- **Set Difference**: $R - S = \{ t \mid t \in R \land t \notin S \}$.
$$0 \le |R - S| \le |R|$$
  *(Note: Non-commutative: $R - S \neq S - R$).*

---

### 2.5 Rename Operator ($\rho$)

Allows renaming of a relation and its attribute names:
- $\rho_{S}(R)$: Renames relation $R$ to $S$.
- $\rho_{S(B_1, B_2, \dots, B_n)}(R)$: Renames relation $R$ to $S$ and simultaneously renames its attributes to $B_1, \dots, B_n$.

---

## 3. Derived Relational Algebra Operators

These operators are defined as syntactical shorthand using the fundamental operators:

### 3.1 Set Intersection ($\cap$)
Defined via set difference:
$$R \cap S = R - (R - S)$$
- Commutative: $R \cap S \equiv S \cap R$.
- Cardinality bounds: $0 \le |R \cap S| \le \min(|R|, |S|)$.

### 3.2 Theta Join ($\bowtie_\theta$)
Combines Cartesian product with selection:
$$R \bowtie_\theta S = \sigma_\theta(R \times S)$$
- **Equi-Join**: A theta join where the condition $\theta$ involves strictly equality comparisons ($A = B$).

### 3.3 Natural Join ($\bowtie$)
An Equi-Join performed on all attributes with **identical names** in $R$ and $S$, projecting out duplicate attribute columns:
$$R \bowtie S = \pi_{\text{Distinct Attributes}}(\sigma_{R.A_1 = S.A_1 \land \dots \land R.A_k = S.A_k}(R \times S))$$
- **Degree**: $\text{deg}(R \bowtie S) = \text{deg}(R) + \text{deg}(S) - \text{Number of Common Attributes}$.
- **Cardinality Bounds**:
$$0 \le |R \bowtie S| \le |R| \times |S|$$
  - If common attribute is a Foreign Key referencing Primary Key in $S$: $|R \bowtie S| = |R|$.

### 3.4 Outer Joins (Preserving Dangling Tuples)
1. **Left Outer Join ($R \leftouterjoin S$)**: Keeps all tuples from $R$; pads missing $S$ attributes with `NULL`.
2. **Right Outer Join ($R \rightouterjoin S$)**: Keeps all tuples from $S$; pads missing $R$ attributes with `NULL`.
3. **Full Outer Join ($R \fullouterjoin S$)**: Keeps all tuples from both $R$ and $S$; pads non-matching attributes with `NULL`.

## 4. The Division Operator ($\div$)

The Division operator ($R \div S$) is specifically designed for queries involving the phrase **"FOR ALL"** or **"EVERY"** (universal quantification).

### 4.1 Schema Requirement & Algebraic Definition
Let relation $R$ have schema $(A_1, \dots, A_m, B_1, \dots, B_n)$ and relation $S$ have schema $(B_1, \dots, B_n)$ where $B \subset A$.
- Schema of $R \div S$: $(A_1, \dots, A_m) = R - S$.
- $R \div S$ returns all tuples $t \in \pi_A(R)$ such that for **every** tuple $s \in S$, the concatenated tuple $\langle t, s \rangle \in R$.

#### Formal Definition in terms of Fundamental Operators:
$$R \div S = \pi_A(R) - \pi_A\left( (\pi_A(R) \times S) - R \right)$$

```text
Step 1: π_A(R)                    -> All candidate A values.
Step 2: π_A(R) × S                -> All possible combinations of candidates with S.
Step 3: (π_A(R) × S) - R          -> Combinations that DO NOT exist in R.
Step 4: π_A(Step 3)               -> Disqualified candidate A values.
Step 5: π_A(R) - Step 4           -> Candidates that paired with EVERY tuple in S.
```

---

### 4.2 Comprehensive Worked Example: Division

**Table: ENROLLED ($R$)**

| Student | Course |
|:---:|:---:|
| Amit | C101 |
| Amit | C102 |
| Amit | C103 |
| Priya | C101 |
| Priya | C102 |
| Rahul | C101 |

**Table: REQUIRED_COURSES ($S$)**

| Course |
|:---:|
| C101 |
| C102 |

**Query**: Find all students who are enrolled in **all** required courses ($R \div S$):
1. Candidate students: $\pi_{\text{Student}}(R) = \{\text{Amit}, \text{Priya}, \text{Rahul}\}$.
2. Cartesian Product: $\pi_{\text{Student}}(R) \times S$:
   - $\langle \text{Amit}, \text{C101} \rangle$, $\langle \text{Amit}, \text{C102} \rangle$
   - $\langle \text{Priya}, \text{C101} \rangle$, $\langle \text{Priya}, \text{C102} \rangle$
   - $\langle \text{Rahul}, \text{C101} \rangle$, $\langle \text{Rahul}, \text{C102} \rangle$
3. Disqualified pairs $[(\pi_{\text{Student}}(R) \times S) - R]$:
   - $\langle \text{Rahul}, \text{C102} \rangle$ is not in $R$!
4. Disqualified students: $\{\text{Rahul}\}$.
5. Result: $\pi_{\text{Student}}(R) - \{\text{Rahul}\} = \mathbf{\{\text{Amit}, \text{Priya}\}}$.

## 5. Tuple Relational Calculus (TRC)

Tuple Relational Calculus is a declarative query language where queries take the form:

$$\{ t \mid P(t) \}$$

where $t$ is a tuple variable and $P(t)$ is a predicate logic formula.

### 5.1 Quantifiers in TRC
- **Existential Quantifier ($\exists$)**: $\exists t \in R (P(t))$ ("There exists a tuple $t$ in $R$ satisfying $P$").
- **Universal Quantifier ($\forall$)**: $\forall t \in R (P(t))$ ("For all tuples $t$ in $R$, $P(t)$ holds").

### 5.2 Duality Equivalence (De Morgan's Laws for Quantifiers)
Competitive exams test quantifier transformation heavily:

$$\forall t \in R (P(t)) \iff \neg \exists t \in R (\neg P(t))$$

$$\exists t \in R (P(t)) \iff \neg \forall t \in R (\neg P(t))$$

---

## 6. Domain Relational Calculus (DRC)

In DRC, variables range over **individual domain attribute values** rather than entire tuples:

$$\{ \langle x_1, x_2, \dots, x_n \rangle \mid P(x_1, x_2, \dots, x_n) \}$$

#### Comparison Example: "Find names of students in CS department"
- **Relational Algebra**: $\pi_{\text{Name}}(\sigma_{\text{Dept} = 'CS'}(\text{Student}))$
- **TRC**: $\{ t.Name \mid t \in \text{Student} \land t.Dept = 'CS' \}$
- **DRC**: $\{ \langle n \rangle \mid \exists i, d (\langle i, n, d \rangle \in \text{Student} \land d = 'CS') \}$

---

## 7. Safety of Calculus Expressions & Codd's Theorem

An expression in TRC or DRC is **unsafe** if it can generate an **infinite relation**.

### 7.1 Unsafe Query Example
$$\{ t \mid \neg (t \in \text{Student}) \}$$
This asks for all tuples in the universe that are *not* in `Student`. Since the universe of potential values is unbounded, this query evaluates to an **infinite set**.

### 7.2 Safe Expressions & Domain Independence
An expression is said to be **safe** if all values that appear in the result are chosen from the **Active Domain** ($\text{dom}(P)$) of the formula: the set of all constant values appearing in the database relations referenced in $P$, plus constants explicitly mentioned in the query.

> **Codd's Equivalence Theorem (Edgar F. Codd, 1972)**:
> **Relational Algebra**, **Safe Tuple Relational Calculus**, and **Safe Domain Relational Calculus** are strictly **equivalent in expressive power**.
> A query language is defined as **relationally complete** if and only if it can express every query that can be formulated in Relational Algebra.

## 8. UGC NET & Bihar STET PYQ Practice Patterns

### Question 1 (UGC NET 2021 — Maximum and Minimum Tuples in Natural Join)
Let $R(A, B)$ have 100 tuples and $S(B, C)$ have 200 tuples. What are the maximum and minimum possible numbers of tuples in $R \bowtie S$?

**Solution**:
1. **Maximum Tuples**:
   - Occurs when all tuples in $R$ and $S$ have the exact same value for the common attribute $B$.
   - Every tuple in $R$ matches with every tuple in $S$:
$$\text{Max Tuples} = |R| \times |S| = 100 \times 200 = \mathbf{20,000}$$
2. **Minimum Tuples**:
   - Occurs when $R$ and $S$ have completely disjoint sets of values for attribute $B$ ($\pi_B(R) \cap \pi_B(S) = \emptyset$).
   - No tuple matches:
$$\text{Min Tuples} = \mathbf{0}$$
**Answer**: Maximum = 20,000; Minimum = 0.

### Question 2 (UGC NET 2019 — Division Operator Equivalent)
Which relational algebra expression is equivalent to $R(A, B) \div S(B)$?
- (A) $\pi_A(R) - \pi_A(\pi_A(R) \times S - R)$
- (B) $\pi_A(R) - \pi_A(R \times S - R)$
- (C) $\pi_A(R \times S) - \pi_A(R)$
- (D) $\pi_A(R) \cap \pi_B(S)$

**Solution**:
- Standard formula for division: $\pi_A(R) - \pi_A((\pi_A(R) \times S) - R)$.
**Answer**: **(A)**.
