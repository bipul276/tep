# E-Commerce Security, Digital Payment Gateways, and SET Protocol

Electronic Commerce is an explicitly defined syllabus domain in the **Bihar STET Computer Science Paper II** (Unit 14). Exam questions test security pillars (Confidentiality, Integrity, Authentication, Non-repudiation), digital payment processing lifecycles, and the cryptographic mechanics of the Secure Electronic Transaction (SET) protocol.

---

## 1. Pillars of E-Commerce Security

| Security Pillar | Meaning in E-Commerce | Cryptographic Solution |
| :--- | :--- | :--- |
| **Confidentiality** | Prevents unauthorized parties from reading transaction details | Symmetric encryption (AES, 3DES) |
| **Integrity** | Ensures transaction data (amount, items) is not tampered with in transit | One-way Hash Functions (SHA-256, HMAC) |
| **Authentication** | Verifies true identities of customer, merchant, and bank | Digital Certificates (X.509, CA), PKI |
| **Non-Repudiation** | Prevents a party from falsely denying they made a purchase or payment | **Digital Signatures** (Asymmetric RSA/ECC) |

---

## 2. Digital Payment Frameworks & Processing

An online payment transaction involves 4 primary parties:
1. **Cardholder (Customer)**: Purchaser initiating payment.
2. **Merchant**: Online seller accepting payment.
3. **Acquiring Bank (Merchant's Bank)**: Processes transactions on behalf of merchant.
4. **Issuing Bank (Customer's Bank)**: Issues credit card or debit account to customer.

```
[Customer Browser] ──HTTPS──► [Merchant Server] ──API──► [Payment Gateway]
                                                               │
                                                       [Acquiring Bank]
                                                               │
                                                        [Payment Switch]
                                                               │
                                                        [Issuing Bank]
```

### 2.1 Smart Cards vs. Magnetic Stripe Cards
- **Magnetic Stripe**: Static data stored on magnetic stripe; vulnerable to cloning/skimming attacks.
- **Smart Card (EMV Chip)**: Contains an embedded **cryptographic microcontroller chip** that generates a dynamic, unique transaction authentication cryptogram for every single transaction, rendering cloned card data useless.

## 3. Secure Electronic Transaction (SET) Protocol

Developed by Visa and MasterCard, SET is an asymmetric cryptographic protocol designed specifically to secure credit card payments over open networks.

### 3.1 The Privacy Dilemma
- The **Merchant** needs to know *what* was ordered (Order Information, OI) and where to ship it, but should NOT see the customer's private credit card number.
- The **Bank** needs to know the payment card number and total amount (Payment Instructions, PI), but should NOT know what specific personal items the customer purchased.

### 3.2 Dual Signature Formulation
To solve this, SET introduces the **Dual Signature ($DS$)**, mathematically binding the order information (OI) and payment instructions (PI) without disclosing both to either party:

$$H_{\text{OI}} = H(\text{OI}), \quad H_{\text{PI}} = H(\text{PI})$$
$$\text{Dual Signature } (DS) = E_{K_{\text{priv\_cardholder}}}\left[ H( H_{\text{OI}} \mathbin{\Vert} H_{\text{PI}} ) \right]$$

*(where $H$ is SHA-1/SHA-256 and $\Vert$ denotes string concatenation)*

### 3.3 Verification Process
1. **Merchant Verification**: Customer sends $[OI, H_{PI}, DS]$.
   - Merchant computes $H(OI)$, concatenates with received $H_{PI}$, and verifies $DS$ using the customer's public key.
   - Merchant verifies authenticity without ever seeing PI!
2. **Bank Verification**: Customer sends $[PI, H_{OI}, DS]$.
   - Bank computes $H(PI)$, concatenates with received $H_{OI}$, and verifies $DS$ using customer's public key.
   - Bank verifies authorization without ever seeing OI!
