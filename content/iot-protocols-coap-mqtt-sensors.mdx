# IoT Communication Protocols: MQTT, CoAP, Zigbee, and Sensors

Internet of Things (IoT) is a high-priority specialized unit in the **Bihar STET Computer Science Paper II** (Unit 12). Competitive exam questions target lightweight messaging protocols (MQTT vs CoAP), wireless sensor networks (Zigbee, 6LoWPAN), RFID systems, and sensor-actuator interfacing.

---

## 1. MQTT (Message Queuing Telemetry Transport)

MQTT is an extremely lightweight, publish-subscribe network protocol designed for constrained devices with low bandwidth and high latency. Operates over **TCP port 1883** (or 8883 with TLS).

### 1.1 Architecture Components
- **Publishers**: Sensor nodes that produce data under specific **Topics** (e.g., `home/livingroom/temperature`).
- **Broker (Server)**: Central hub that receives messages, filters them by topic, and distributes them to subscribers.
- **Subscribers**: Client applications that register interest in topics to receive updates.

### 1.2 MQTT Quality of Service (QoS) Levels

| QoS Level | Guarantee | Overhead | Mechanism |
| :---: | :--- | :---: | :--- |
| **QoS 0** | **At most once** (Fire and Forget) | Lowest (1 packet) | No ACK, no retransmission; message loss possible |
| **QoS 1** | **At least once** | Medium (2 packets) | Sender retransmits until `PUBACK` is received; duplicates possible |
| **QoS 2** | **Exactly once** | Highest (4 packets) | 4-step handshake (`PUBLISH  PUBREC  PUBREL  PUBCOMP`); zero loss, zero duplicates |

<Callout type="note">
**MQTT Last Will and Testament (LWT)**: Allows a client to specify a message that the broker will automatically publish on its behalf if the client unexpectedly disconnects (e.g., battery failure).
</Callout>

## 2. CoAP (Constrained Application Protocol)

CoAP is a specialized web transfer protocol designed by IETF (RFC 7252) for machine-to-machine (M2M) applications.
- Operates over **UDP port 5683** (or 5684 with DTLS).
- Implements a subset of **REST** (`GET, POST, PUT, DELETE`).
- Message Types:
  1. **Confirmable (CON)**: Requires an acknowledgment (`ACK`) from the receiver.
  2. **Non-Confirmable (NON)**: Fire-and-forget datagram without ACK.
  3. **Acknowledgment (ACK)**: Confirms receipt of a CON message.
  4. **Reset (RST)**: Rejects an unprocessable message.

### 2.3 MQTT vs. CoAP Comparison

| Feature | MQTT | CoAP |
| :--- | :--- | :--- |
| **Transport** | TCP (Connection-oriented) | **UDP** (Connectionless) |
| **Architecture** | Centralized Broker (Pub/Sub) | Decentralized / Peer-to-Peer (Client/Server) |
| **Header Overhead** | **2 Bytes** minimum fixed header | 4 Bytes fixed header |
| **Communication** | Asynchronous many-to-many | Synchronous request/response (supports Observe) |
| **Security** | TLS/SSL | **DTLS** (Datagram TLS) |

## 3. Wireless Sensor Network Protocols

1. **Zigbee (IEEE 802.15.4)**:
   - Low-power, low data rate (250 kbps), operating at 2.4 GHz, 868 MHz, and 915 MHz.
   - Topologies: Star, Tree, and **Mesh**.
   - Transmission range: 10 to 100 meters.
2. **6LoWPAN (IPv6 over Low-Power Wireless Personal Area Networks)**:
   - Enables native IPv6 packets to be transmitted over constrained IEEE 802.15.4 links.
   - Employs **header compression** (reducing 40-byte IPv6 headers to 2-4 bytes) and packet fragmentation (accommodating 1280-byte IPv6 MTU within 127-byte 802.15.4 frame).
3. **RFID (Radio Frequency Identification)**:
   - **Passive Tags**: Contain no internal battery; powered by the electromagnetic field induced by the reader's interrogating antenna.
   - **Active Tags**: Powered by internal batteries; transmit over greater distances (up to 100m).
