# Memory Management, Multi-Level Paging, TLB, Inverted Tables & Virtual Memory

## 1. Physical vs. Logical Address Space

In modern operating systems, the CPU generates **logical (virtual) addresses** during program execution. The physical memory (RAM) is organized into hardware-addressable locations called **physical addresses**.

The hardware mapping between logical addresses and physical addresses is managed by the **Memory Management Unit (MMU)**:

```text
+-----+   Logical Address    +-------+   Physical Address   +-------------+
| CPU | -------------------> |  MMU  | -------------------> | Main Memory |
+-----+   (e.g., 0x00401000) +-------+   (e.g., 0x1A201000) +-------------+
```

### 1.1 Contiguous Memory Allocation & Fragmentation
- **Internal Fragmentation**: Occurs when memory is allocated in fixed-size blocks (e.g., fixed partitions or paging). If a process requires less memory than the allocated block, the unused space inside the block is wasted.
- **External Fragmentation**: Occurs when dynamic partitions create small, non-contiguous free memory holes throughout physical memory. The total free space may be sufficient to satisfy a request, but no single contiguous block is large enough.
  - *Remedy*: Paging (non-contiguous allocation) or Compaction.

---

## 2. Paging Architecture & Address Translation

Paging eliminates external fragmentation by allowing a process's physical address space to be **non-contiguous**.

### 2.1 Basic Structure: Pages and Frames
- **Frames**: Physical memory is broken into fixed-size contiguous blocks called **frames**.
- **Pages**: Logical memory is broken into blocks of the **exact same size** called **pages**.
- **Frame Size = Page Size** (typically $4 \text{ KB} = 2^{12} \text{ bytes}$).

```text
Logical Address (Generated by CPU):
+-----------------------------------+-----------------------------------+
|          Page Number (p)          |          Page Offset (d)          |
+-----------------------------------+-----------------------------------+
                 |                                    |
                 v (Lookup in Page Table)             |
+-----------------------------------+                 |
|          Frame Number (f)         |                 |
+-----------------------------------+                 |
                 |                                    |
                 v                                    v
+-----------------------------------+-----------------------------------+
|          Frame Number (f)         |          Page Offset (d)          |
+-----------------------------------+-----------------------------------+
Physical Address (Sent to RAM):
```

---

### 2.2 Address Translation Mathematics

Let:
- Logical Address Space $= 2^m$ bytes $\implies m$-bit Logical Address.
- Physical Address Space $= 2^n$ bytes $\implies n$-bit Physical Address.
- Page Size (and Frame Size) $= 2^d$ bytes $\implies d$-bit Offset.

$$\text{Number of Pages} = \frac{\text{Logical Address Space}}{\text{Page Size}} = \frac{2^m}{2^d} = 2^{m - d}$$
$$\text{Number of Frames} = \frac{\text{Physical Address Space}}{\text{Frame Size}} = \frac{2^n}{2^d} = 2^{n - d}$$

- **Page Number Bits ($p$)**: $p = m - d$
- **Frame Number Bits ($f$)**: $f = n - d$
- **Page Offset Bits ($d$)**: $d = \log_2(\text{Page Size})$

---

### 2.3 Page Table Entry (PTE) Structure

A Page Table Entry contains the translation metadata for each virtual page:

| Field | Size | Purpose |
|---|:---:|---|
| **Frame Number** | $f$ bits | Specifies the physical frame where the page resides |
| **Valid / Invalid Bit** | 1 bit | `1` = Page is in physical RAM; `0` = Page is on disk (causes **Page Fault**) |
| **Dirty (Modified) Bit** | 1 bit | `1` = Page modified in RAM; must be written back to disk on eviction |
| **Reference (Access) Bit** | 1 bit | `1` = Page has been accessed recently; used by Clock / LRU replacement |
| **Protection Bits** | 2-3 bits | Read, Write, Execute (`rwx`) permissions |

---

## 3. Multi-Level (Hierarchical) Paging

In modern 32-bit and 64-bit architectures, a flat page table is too large to store contiguously in memory:
- With a 32-bit address space and 4 KB pages ($2^{12}$ B), there are $2^{20} \approx 1,048,576$ pages.
- At 4 bytes per PTE, a single page table requires **4 MB per process**!

**Multi-Level Paging** divides the page table itself into pages, allowing non-contiguous storage and demand allocation of page table pages.

### 3.1 Two-Level Paging Bit-Splitting Rule
The fundamental architectural constraint:
$$\text{The inner (second-level) page table must fit exactly within ONE page frame!}$$

$$\text{Entries per Page Frame} = \frac{\text{Page Size}}{\text{PTE Size}} = 2^{p_2}$$

```text
32-Bit Logical Address (Two-Level):
+-----------------------+-----------------------+-----------------------+
|  Outer Page Index (p₁) |  Inner Page Index (p₂) |    Page Offset (d)    |
|        10 bits        |        10 bits        |        12 bits        |
+-----------------------+-----------------------+-----------------------+
```

#### Step-by-Step Numerical:
For a 32-bit system with 4 KB pages and 4-byte PTE:
1. Offset: $d = \log_2(4096) = 12 \text{ bits}$.
2. Inner Page Table entries per frame: $\frac{4096}{4} = 1024 = 2^{10} \implies p_2 = 10 \text{ bits}$.
3. Outer Page Table bits: $p_1 = 32 - p_2 - d = 32 - 10 - 12 = \mathbf{10 \text{ bits}}$.

---

## 4. Inverted Page Table

Unlike standard page tables that grow with virtual memory size, an **Inverted Page Table** has exactly one entry for each **physical memory frame**:

- **Size of Table**: Proportional to **Physical Memory**, independent of virtual address space or number of processes.
- **Entry Structure**: $\langle \text{PID}, \text{Page Number} \rangle$
- **Lookup Overhead**: Searching the table requires linear search $O(\text{Frames})$.
  - *Remedy*: Augmented with a hardware **Hash Table** for $O(1)$ average lookup.

---

## 5. Translation Lookaside Buffer (TLB) & Effective Memory Access Time (EMAT)

Because page tables reside in main memory, every standard memory access requires **two memory accesses**:
1. Access main memory to read the Page Table Entry.
2. Access main memory to read/write the actual data word.

To eliminate this 100% latency penalty, the MMU includes a specialized high-speed associative hardware cache called the **Translation Lookaside Buffer (TLB)**.

```text
CPU generates Virtual Address:
          |
          v
   +--------------+     TLB HIT (h)
   |  Search TLB  | ----------------------> Directly obtain Frame Number
   +--------------+                         (Fast: 1 memory access)
          |
          | TLB MISS (1 - h)
          v
   +--------------+
   | Search Page  | ----------------------> Load Frame into TLB
   |    Table     |                         (Slow: 2+ memory accesses)
   +--------------+
```

---

### 5.1 EMAT Formulas

Let:
- $h$: TLB hit ratio ($0 \le h \le 1$).
- $T_{\text{tlb}}$: TLB lookup latency.
- $T_{\text{mem}}$: Main memory access latency.

#### Case 1: Single-Level Paging with TLB
$$\text{EMAT} = h \times (T_{\text{tlb}} + T_{\text{mem}}) + (1 - h) \times (T_{\text{tlb}} + 2 \cdot T_{\text{mem}})$$

*(If TLB search and Page Table access occur in parallel: $\text{EMAT} = h \cdot T_{\text{mem}} + (1 - h) \cdot 2T_{\text{mem}}$).*

#### Case 2: Multi-Level ($k$-Level) Paging with TLB
On a TLB miss, the MMU must traverse all $k$ levels of the page table hierarchy before reaching the actual data frame ($k + 1$ memory accesses total):

$$\text{EMAT} = h \times (T_{\text{tlb}} + T_{\text{mem}}) + (1 - h) \times [T_{\text{tlb}} + (k + 1) \cdot T_{\text{mem}}]$$

---

### 5.2 Worked Numerical: Two-Level Paging EMAT

**Problem (UGC NET Style)**:
A computer uses a 2-level paging scheme with a TLB:
- TLB access time $T_{\text{tlb}} = 10 \text{ ns}$.
- Main memory access time $T_{\text{mem}} = 100 \text{ ns}$.
- TLB hit ratio $h = 0.90$ (90%).
Calculate the Effective Memory Access Time (EMAT).

**Solution**:
1. On TLB Hit: $T_{\text{hit}} = T_{\text{tlb}} + T_{\text{mem}} = 10 + 100 = 110 \text{ ns}$.
2. On TLB Miss: Access Outer Table + Inner Table + Data Frame:
$$T_{\text{miss}} = T_{\text{tlb}} + (2 + 1) \times T_{\text{mem}} = 10 + 3 \times 100 = 310 \text{ ns}
$$
3. Overall EMAT:
$$
\begin{aligned}
   \text{EMAT} &= (0.90 \times 110) + (0.10 \times 310) \\
   &= 99 + 31 = \mathbf{130 \text{ ns}}
   \end{aligned}
$$

## 6. Demand Paging & Page Fault Handling

In a virtual memory system, pages are loaded into memory only when demanded during execution (**Demand Paging**).

### 6.1 Page Fault Sequence (Step-by-Step)
1. CPU references memory location on virtual page $p$.
2. MMU checks Page Table: Valid bit is `0` $\implies$ **Page Fault Trap** to OS kernel.
3. OS saves process state / registers.
4. OS checks if memory address is a valid reference (if invalid $\implies$ terminate process with Segmentation Fault).
5. OS locates desired page on backing store (swap space / disk).
6. OS finds a free physical frame in RAM (if no free frame $\implies$ execute a **Page Replacement Algorithm** to evict a victim page).
7. OS schedules disk I/O to read page into chosen frame.
8. When I/O completes, OS updates Page Table: sets Frame Number and marks Valid bit $= 1$.
9. OS restores process state and **restarts the instruction** that caused the fault.

### 6.2 EMAT with Page Faults
$$\text{EMAT} = (1 - p) \times T_{\text{mem}} + p \times \text{Page Fault Service Time (PFST)}$$
*(Since disk access is measured in milliseconds and RAM in nanoseconds, even a $0.1\%$ page fault rate degrades system throughput by over $1000\times$!).*

---

## 7. Page Replacement Algorithms

When a page fault occurs and no physical frames are free, the OS must choose a **victim page** to evict.

### 7.1 FIFO (First-In, First-Out) & Belady's Anomaly

- **Rule**: Evicts the page that has been in memory for the longest time.
- **Belady's Anomaly**: For some page replacement algorithms, **increasing the number of allocated physical frames leads to an INCREASE in the number of page faults!**

#### Proof of Belady's Anomaly with Reference String:
$$1, 2, 3, 4, 1, 2, 5, 1, 2, 3, 4, 5$$

- **With 3 Frames**: Exactly **9 page faults**.
- **With 4 Frames**: Exactly **10 page faults**!
*(Having more memory caused more page faults!).*

---

### 7.2 Optimal Page Replacement (OPT / MIN / Belady's Algorithm)

- **Rule**: Replace the page that will **not be used for the longest period of time in the future**.
- **Property**: Provably achieves the lowest possible page fault rate for any fixed reference string.
- **Implementation**: Unachievable in real operating systems (requires clairvoyant knowledge of future memory references). Used as a theoretical benchmark.

---

### 7.3 LRU (Least Recently Used)

- **Rule**: Replace the page that has **not been referenced for the longest period of time in the past** (approximates OPT using backward-looking locality).
- **Property**: Belongs to the class of **Stack Algorithms**.
  > **Theorem**: A stack algorithm is mathematically immune to Belady's Anomaly. Adding frames will **never** increase the number of page faults in LRU.

---

### 7.4 Second-Chance (Clock) Algorithm

Approximates LRU with low hardware overhead using a 1-bit Reference Bit and a circular queue pointer (clock hand):
1. When a victim is needed, inspect the page pointed to by the hand:
   - If Reference Bit $= 0$: **Evict this page** and advance hand.
   - If Reference Bit $= 1$: Clear bit to $0$ ("give it a second chance"), advance hand, and inspect next page.

---

## 8. Thrashing & The Working Set Model

### 8.1 Thrashing
**Thrashing** occurs when a system spends more time servicing page faults and swapping pages in/out of disk than executing useful user instructions.
- As degree of multiprogramming increases, CPU utilization rises up to a peak, then collapses catastrophically to near zero.

```text
CPU Utilization
   ^           Peak
   |          /----\
   |         /      \  THRASHING CRASH
   |        /        \
   |       /          \
   +----------------------> Degree of Multiprogramming
```

### 8.2 The Working Set Model (Peter Denning)
- **Working Set Window ($\Delta$)**: A fixed number of recent page references.
- **Working Set ($WS_i$)**: The set of distinct pages referenced by process $P_i$ in the most recent $\Delta$ time units.
- **Total Memory Demand**:
$$D = \sum_{i=1}^{k} |WS_i|$$
- **Thrashing Prevention Criterion**:
  If total demand $D > \text{Total Available Frames}$, the OS must **suspend (swap out)** one or more processes to bring $D \le \text{Total Frames}$.

## 9. UGC NET & Bihar STET PYQ Practice Patterns

### Question 1 (UGC NET 2021 — Multi-Level Paging Bits)
A 32-bit virtual address system uses 2-level paging. The page size is 4 KB and each page table entry takes 4 bytes. What are the bit allocations for the first level index, second level index, and offset?

**Solution**:
1. Page size $= 4\text{ KB} = 2^{12}\text{ bytes} \implies \text{Offset } d = 12 \text{ bits}$.
2. A single page frame can store:
$$\frac{\text{Page Size}}{\text{PTE Size}} = \frac{4096 \text{ B}}{4 \text{ B}} = 1024 = 2^{10} \implies p_2 = 10 \text{ bits}$$
3. Outer page table bits:
$$p_1 = 32 - 10 - 12 = \mathbf{10 \text{ bits}}$$
**Answer**: Level 1 = 10 bits, Level 2 = 10 bits, Offset = 12 bits.

### Question 2 (UGC NET 2020 — Page Replacement Fault Trace)
Consider the reference string: $7, 0, 1, 2, 0, 3, 0, 4, 2, 3$ with **3 frames** initially empty. How many page faults occur under FIFO?

**Solution**:
1. `7`: Fault $\to [7, -, -]$
2. `0`: Fault $\to [7, 0, -]$
3. `1`: Fault $\to [7, 0, 1]$
4. `2`: Fault (Evicts oldest: 7) $\to [2, 0, 1]$
5. `0`: **HIT** $\to [2, 0, 1]$
6. `3`: Fault (Evicts oldest: 0) $\to [2, 3, 1]$
7. `0`: Fault (Evicts oldest: 1) $\to [2, 3, 0]$
8. `4`: Fault (Evicts oldest: 2) $\to [4, 3, 0]$
9. `2`: Fault (Evicts oldest: 3) $\to [4, 2, 0]$
10. `3`: Fault (Evicts oldest: 0) $\to [4, 2, 3]$

Total faults $= \mathbf{9 \text{ page faults}}$ (1 hit at step 5).
**Answer**: 9 page faults.
