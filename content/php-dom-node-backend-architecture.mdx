# Web Backend Architecture: PHP, DOM Manipulation, and Node.js Event Loop

Web development is an explicitly tested module in the **Bihar STET Computer Science Paper II** (Unit 10). Questions examine server-side PHP scripting, superglobal arrays, Document Object Model (DOM) event bubbling and capturing, and the asynchronous single-threaded Event Loop architecture of Node.js.

---

## 1. PHP Server-Side Scripting

PHP (Hypertext Preprocessor) is an open-source, interpreted, server-side scripting language embedded within HTML.

### 1.1 Variables and Scope
- Variables are prefixed with `$` (e.g., `$x = 10;`).
- Dynamically typed with loose type comparison (`==` compares value; `===` compares value and type).
- **Scope**: Local, Global (accessed inside functions via `global $var;` or `$GLOBALS['var']`), and Static (retains value across repeated function calls).

### 1.2 PHP Superglobal Arrays

| Superglobal | Purpose | Visibility / Lifetime |
| :--- | :--- | :--- |
| **`$_GET`** | Data passed via URL query string parameters (`?key=val`) | Visible in browser URL; max length limited (~2048 chars) |
| **`$_POST`** | Data passed via HTTP POST request body (form submissions) | Hidden from URL; supports binary file uploads; secure |
| **`$_SESSION`** | User session state stored on the **server** | Persists across pages until browser closes or session destroyed |
| **`$_COOKIE`** | Small text data stored on the **client browser** | Sent with every HTTP request header; expires on set timestamp |
| **`$_FILES`** | Multi-dimensional array holding uploaded file attributes (`name, type, size, tmp_name, error`) | Available during multipart form submission |
| **`$_SERVER`** | Header, path, and script location information (`REQUEST_METHOD`, `REMOTE_ADDR`) | Server environment metadata |

<Callout type="important">
**Session vs Cookie Security**:
- `session_start()` must be called before ANY HTML output is sent.
- Session IDs are stored in a cookie (typically `PHPSESSID`), but sensitive data remains on the server.
- Cookies can be modified or disabled by the client; sessions cannot be directly tampered with by the client.
</Callout>

## 2. Document Object Model (DOM) Architecture

The DOM represents an HTML/XML document as a hierarchical tree of nodes (`Document  Element  Text / Attribute`).

### 2.1 DOM Selection and Mutation
```javascript
// Selection primitives
const elem = document.getElementById("header");
const items = document.querySelectorAll(".item"); // Returns static NodeList

// Mutation primitives
const newDiv = document.createElement("div");
newDiv.textContent = "New Node";
elem.appendChild(newDiv);
```

### 2.2 Event Propagation: Bubbling vs. Capturing
When an event occurs on an element nested inside parent elements, it travels in two phases:
1. **Capturing Phase (Trickling)**: Event travels from the `window` down through parents to the target element (`addEventListener(event, fn, true)`).
2. **Target Phase**: Event triggers on the target element itself.
3. **Bubbling Phase**: Event bubbles **upward** from the target element through all its ancestor parent elements up to `window` (default behavior: `addEventListener(event, fn, false)`).
- **`e.stopPropagation()`**: Halts traversal up or down the DOM tree.
- **`e.preventDefault()`**: Prevents standard browser default action (e.g. form submission or hyperlink navigation).

## 3. Node.js Architecture & Asynchronous Event Loop

Node.js is an open-source, cross-platform runtime environment executing JavaScript outside the browser using Google's **V8 Engine** and **libuv**.

### 3.1 Single-Threaded Non-Blocking I/O
Node.js runs JavaScript application code on a **single main thread**, delegating heavy file I/O, network sockets, and cryptographic operations to the **libuv thread pool** (default: 4 worker threads).

### 3.2 The Event Loop Phases
The libuv Event Loop cycles continuously through 6 distinct phases in strict FIFO order:

```
┌───────────────────────────────────────────┐
│              1. Timers                    │  setTimeout(), setInterval() callbacks
└─────────────────────┬─────────────────────┘
                      ▼
┌───────────────────────────────────────────┐
│        2. Pending I/O Callbacks           │  Deferred OS I/O callbacks (e.g. TCP errors)
└─────────────────────┬─────────────────────┘
                      ▼
┌───────────────────────────────────────────┐
│          3. Idle, Prepare                 │  Used internally by libuv
└─────────────────────┬─────────────────────┘
                      ▼
┌───────────────────────────────────────────┐
│             4. Poll Phase                 │  Retrieves new I/O events; blocks if waiting
└─────────────────────┬─────────────────────┘
                      ▼
┌───────────────────────────────────────────┐
│            5. Check Phase                 │  setImmediate() callbacks executed here!
└─────────────────────┬─────────────────────┘
                      ▼
┌───────────────────────────────────────────┐
│        6. Close Callbacks                 │  e.g., socket.on('close', ...)
└───────────────────────────────────────────┘
```

<Callout type="warning">
**Microtask Priority**:
- `process.nextTick()` and `Promise.then()` microtasks are NOT phases of the event loop.
- They execute **immediately after the current synchronous operation completes**, BEFORE the event loop transitions to the next phase!
</Callout>
